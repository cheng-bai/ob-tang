# 试卷 MD 加工到讲义生成工作流

## 目标

把外部转换得到的试卷 Markdown 纳入资料库，并逐步加工成可用于 LaTeX 讲义生成的规范材料。

长期链路：

```text
原始试卷 PDF/图片
-> 转换为 Markdown
-> 保留原始 MD
-> 生成加工版 MD
-> 建立单题索引
-> 组卷 / 备课 / 讲义生成
-> LaTeX 专业排版
-> PDF 讲义
```

## 文件分层

### 1. 原始转换稿

建议放在：

```text
0-一模-二模-模考试卷-md版本/md输出/试卷名/试卷名.md
```

要求：

- 尽量保留转换器原始输出
- 不直接在原始稿上反复手改
- 图片目录与 Markdown 保持相对路径可追踪

### 2. 加工版 Markdown

由脚本输出到：

```text
outputs/试卷MD加工/
```

加工版用于教学生产，包含：

- 统一 frontmatter
- 试卷信息
- 知识点总览
- 每题题干
- 答案
- 解析
- 知识模块
- 核心知识点
- 题意理解
- 方法标签
- 能力标签
- 易错标签
- 讲义用途
- 学生易卡点

## 标准加工命令

```bash
make polish-md input=原始试卷.md output=outputs/试卷MD加工/试卷名-加工版.md
```

等价命令：

```bash
python3 pipeline/build/润色试卷MD.py \
  --input 原始试卷.md \
  --output outputs/试卷MD加工/试卷名-加工版.md
```

如果不指定 `output`，脚本会默认输出到：

```text
outputs/试卷MD加工/{原文件名}-加工版.md
```

## 日志管理

### 机器日志

加工脚本会追加：

```text
00-索引与配置/加工日志.jsonl
```

每条记录包含：

- 执行时间
- 输入路径
- 输出路径
- 题目数
- 知识点数
- 待分类题目数

### 标签分层要求

标签的目标是筛出可复用题，不是把所有题都变复杂。基础套公式题只做简洁标注；中档题、综合题、压轴题才做完整细粒度标注。

基础题保留：

- `知识模块`：保留原始大类，便于索引兼容。
- `标注层级`：写作 `基础题简洁标注`。
- `难度` / `分值`

可复用题保留：

- `标注层级`：写作 `可复用题完整标注`。
- `核心知识点`：具体到可讲授的知识动作，例如“导数几何意义”“条件样本空间修正”“直线与双曲线联立”。
- `题意理解`：用一句话说明这题到底在考什么。
- `方法标签`：记录解法入口，例如“联立消元”“分类讨论”“相邻概率比值法”。
- `能力标签`：记录能力侧重点，例如“运算求解”“逻辑推理”“空间想象”。
- `易错标签`：记录学生最可能错在哪里。
- `讲义用途`：标明适合放入“基础巩固”“易错讲评”“压轴训练”等位置。

当前默认规则：

- 第 1-7 题按基础题处理。
- 第 8 题以后按可复用题处理。
- 解答题无论题号如何，都按可复用题处理。

`knowledge_points` 和“知识点总览”只收录可复用题的核心知识点，避免简单题制造噪音。正文总览中的题号必须写成完整标题锚点链接，例如 `[第 11 题](#第-11-题填空)`，不要插入 `<a id="..."></a>` 这类裸 HTML 标签。

知识点总览必须按上海高中数学常见板块分组，优先使用：

- 函数、不等式与方程
- 三角函数与平面向量
- 数列
- 解析几何
- 立体几何与空间向量
- 概率统计
- 计数原理

每个 frontmatter 知识点条目应包含 `block` 和 `levels`，正文题号后应标注题目层级，例如 `[第 20 题](#第-20-题解答)（压轴题）`。

核心知识点必须收窄：

- 填空题、选择题最多保留 2 个核心知识点。
- 解答题最多保留 3 个核心知识点。
- 不把所有相关知识都塞进 `核心知识点`；次要条件、辅助公式和过程性方法放到 `方法标签` 或不写。

索引重建脚本会追加：

```text
00-索引与配置/运行日志.jsonl
```

### 人工记录

重要批次加工后，在 `docs/工作记录/` 下新增当天记录，说明：

- 本批处理了哪些试卷
- 输出到哪里
- 发现了哪些格式问题
- 哪些题需要人工复核
- 是否已经进入索引

## 入库后的必要动作

加工完成后执行：

```bash
make index
```

检查：

```bash
make search keyword=目标知识点
make exam topic=目标知识点 count=3 output=build/验证.md
```

验证后删除临时 `build/验证.md`。

## AI 后续处理规范

当用户提供新的试卷 Markdown 时，AI 应按以下顺序执行：

1. 确认原始 MD 所在路径，不覆盖原文件。
2. 运行 `pipeline/build/润色试卷MD.py` 生成加工版。
3. 检查加工版是否包含题干、答案、解析、知识点、易卡点。
4. 运行 `make index` 让新材料进入索引。
5. 用 `make exam` 或 `make search` 做最小验证。
6. 将批次结果写入 `docs/工作记录/`。

## 面向 LaTeX 讲义的下一步

加工版 Markdown 不是终点，而是讲义生成的中间层。后续应继续建设：

- Markdown 到 LaTeX 题目环境的转换
- `exercise` / `realexam` / `example` 等讲义环境映射
- 学生版隐藏解析、教师版保留解析
- 图片路径复制与 LaTeX 引用
- 版式模板、页眉页脚、答案区、讲评区

最终目标是：

```text
加工版 MD -> 结构化题目数据 -> LaTeX 讲义 -> PDF
```
