# 跨 AI 记忆导入工作流

## 目标

把用户在其他 AI、IDE 插件、聊天工具、知识库或本地 Agent 中形成的长期记忆导出，清洗成一个可复用的上下文包，让新的 AI 能快速理解用户画像、项目结构、写作偏好、LaTeX 审美、常用流程和历史决策。

核心原则：不要把原始聊天记录直接整包塞给 AI，而是先分层整理、去敏、摘要、索引，再按任务需要加载。

## 适用来源

常见来源包括：

- ChatGPT / Claude / Gemini 等聊天记录导出。
- Cursor、Claude Code、Kimi、OpenClaw、Hermes、Alma 等本地或 IDE Agent 记忆。
- Obsidian / RemNote / Logseq 等知识库。
- 项目内的 `AGENTS.md`、`README.md`、`docs/`、任务日志、日报周报。
- 个人长期偏好文档、教学工作流文档、LaTeX 模板规范。

## 推荐输出结构

建议在项目或全局记忆库中建立如下结构：

```text
ai-context/
├── README.md                    # 给 AI 看的总入口
├── profile.md                   # 用户画像与稳定偏好
├── projects.md                  # 项目目录、用途、当前状态
├── workflows.md                 # 常用工作流
├── style-guide.md               # 写作、排版、LaTeX、前端审美
├── decisions.md                 # 长期决策与原因
├── task-patterns.md             # 常见指令到执行策略的映射
├── glossary.md                  # 用户自己的术语表
├── import-log.md                # 每次导入记录
└── raw/                         # 原始导出，仅归档，不默认加载
```

## 导入流程

### 1. 导出

从其他 AI 或工具导出原始资料，优先选择 Markdown、JSON、HTML、TXT 这类可解析格式。

导出后不要直接覆盖现有上下文，先放入：

```text
ai-context/raw/YYYY-MM-DD-source-name/
```

### 2. 去敏

必须先检查并处理以下内容：

- API Key、Token、Cookie、密钥文件路径。
- 手机号、身份证、住址、学生完整隐私信息。
- 私有仓库访问凭证。
- 不希望长期保留的临时情绪、临时吐槽、一次性上下文。

敏感信息处理原则：

- 凭证删除，不做摘要。
- 学生信息匿名化。
- 项目路径可以保留，但账号、密钥、会话 ID 不保留。

### 3. 分层

把原始材料拆成四层：

- 稳定层：长期不变的信息，如职业、主要项目、LaTeX 审美、常用目录。
- 项目层：每个项目的结构、入口、脚本、验证方式和风险。
- 流程层：可重复执行的工作流，如试卷切分、讲义生成、PDF 导出。
- 情境层：近期任务、未完成事项、一次性决策。

只有稳定层和项目层适合长期加载；情境层要带日期和过期提醒。

### 4. 压缩

每批导入都要形成一个短摘要：

```markdown
## 来源

- 工具：
- 导出时间：
- 文件范围：

## 可长期保留

- ...

## 只适合近期参考

- ...

## 不应导入

- ...

## 下次 AI 应自动采用的规则

- ...
```

### 5. 建索引

每条记忆都要能回答三个问题：

- 这条记忆适用于哪个项目？
- 什么时候可能过期？
- AI 应该如何使用它？

建议格式：

```markdown
## 记忆标题

- scope：
- source：
- updated：
- expires：
- use_when：
- rule：
```

## 上下文包入口模板

`ai-context/README.md` 推荐写成下面的形式：

```markdown
# AI 上下文入口

你正在协助一名高中数学教师维护本地数学教学工作流。

## 必读顺序

1. `profile.md`
2. `projects.md`
3. 当前项目的 `AGENTS.md`
4. 与本次任务相关的 workflow 文档

## 使用规则

- 不确定当前状态时，先检查真实文件。
- 不要把旧记忆当作当前事实；路径、依赖、接口、脚本状态需要现场验证。
- 涉及凭证、API、外部工具版本时必须重新确认。
- 完成任务后追加任务记录和复盘。
```

## 给本项目的使用方式

在 `latex-maki-math` 中，跨 AI 记忆应服务于三件事：

1. 让 AI 立刻理解 Maki 风格讲义的写作和排版要求。
2. 让 AI 复用已经验证过的试卷拆分、讲义生成、PDF/HTML 导出流程。
3. 让 AI 知道用户常用指令的真实含义，例如“开始执行”“继续”“只要题目”“输出 PDF”。

本项目可接入的文件：

- `AGENTS.md`
- `README.md`
- `docs/自我复盘与迭代机制.md`
- `00-索引与配置/任务执行记录.md`
- 后续新增的 `ai-context/` 上下文包

## 最小可行方案

第一阶段不做复杂系统，只做一个可维护的本地上下文包：

1. 建立 `ai-context/`。
2. 把其他 AI 导出的原始资料放入 `ai-context/raw/`。
3. 人工或 AI 半自动整理出 `profile.md`、`projects.md`、`workflows.md`、`style-guide.md`。
4. 在每个项目根目录 `AGENTS.md` 中链接对应上下文。
5. 每次任务结束把新规则写回项目任务记录。

## 质量标准

合格的跨 AI 记忆不是“越多越好”，而是：

- 新 AI 读完 3-5 个入口文件，就能正确开始工作。
- 记忆里有明确适用范围和过期风险。
- 不泄露凭证和学生隐私。
- 不用旧记忆覆盖真实文件检查。
- 能把用户的常用指令翻译成稳定执行策略。
