# 自我复盘与迭代机制

## 目标

让 AI 在本项目中形成稳定的“完成任务 -> 复盘 -> 迭代 -> 进化”闭环。每次不只交付一个结果，还要把有效经验沉淀下来，减少以后重复沟通和重复试错。

## 每次任务的闭环

### 1. 执行前

- 明确任务类型：讲义编写、试卷拆分、题库整理、PDF/HTML 导出、项目治理、技能封装。
- 找到真实源文件和目标输出目录。
- 读取已有模板、脚本、样式和同类历史产物。
- 对不确定项做最小澄清；如果用户已说“开始执行”，优先做保守可逆的实现。

### 2. 执行中

- 保持改动范围小，优先复用现有结构。
- 对数学内容进行条件、符号、结论、图文关系检查。
- 对批量任务保留日志或报告，不只给口头总结。
- 生成文件时保留来源、处理人、处理时间或等价的 provenance 信息。

### 3. 执行后

在 `00-索引与配置/任务执行记录.md` 追加记录：

```markdown
## YYYY-MM-DD HH:mm — 任务标题

- 任务类型：
- 输入文件：
- 输出文件：
- 已验证：
- 未验证/风险：
- 复盘：
- 迭代：
- 进化规则：
```

## 复盘标准

复盘不是写流水账，而是回答三个问题：

- 这次真正解决了什么问题？
- 哪一步最容易下次复用？
- 哪个风险如果不记录，下次会再次踩坑？

## 迭代标准

符合以下任一条件，就应该沉淀为规范、脚本或 Skill：

- 同类任务预计会重复 3 次以上。
- 手工步骤超过 5 步。
- 涉及 LaTeX 编译、图片路径、题号重排、答案剥离等容易出错环节。
- 用户已经明确认可某个流程或模板。

## 进化规则写法

进化规则要短、可执行，避免空话。

好例子：

- 遇到“仅题目版”，自动删除答案、解析、提示、评分标准，只保留题干、选项、图表。
- 遇到“输出 PDF”，必须检查 PDF 是否真实生成，并报告路径。
- 遇到“图片没跟题目”，优先修复 Markdown/LaTeX 中图片位置，再导出。

坏例子：

- 下次要更认真。
- 以后要注意质量。
- 优化工作流。

## 项目当前默认规则

- 根目录 `README.md` 负责说明项目结构和编译方式。
- 根目录 `AGENTS.md` 负责给 AI 说明执行规则。
- `00-索引与配置/任务执行记录.md` 负责记录每次任务。
- `docs/` 负责放稳定规范、流程说明和复盘机制。
- `Skills/` 只放已经验证过、可以复用的工具或技能，不放一次性草稿。
