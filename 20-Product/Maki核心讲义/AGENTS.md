# AGENTS.md — latex-maki-math AI 协作规则

## 项目定位

本项目用于维护高中数学 Maki 风格讲义、真题拆分材料、专题讲义和相关导出产物。AI 的默认职责不是只回答建议，而是读取真实文件、完成可验证产物、记录过程，并把可复用经验沉淀为项目规则。

## 默认执行方式

当用户说“开始执行”“继续执行”“接手完成”时，按下面顺序工作：

1. 先读取当前目录结构、入口文档、相关源文件和已有输出。
2. 判断任务属于讲义编写、试卷拆分、PDF/HTML 导出、知识库维护、技能封装还是项目治理。
3. 优先复用现有模板、脚本和目录，不随意另起一套结构。
4. 产出必须落到文件中，并尽量给出可打开、可编译、可复查的结果。
5. 完成后更新 `00-索引与配置/任务执行记录.md`。
6. 如果发现可复用流程，补充到 `docs/自我复盘与迭代机制.md` 或独立 workflow 文档。

## Karpathy 风格执行约束

本项目启用 `karpathy-guidelines` 作为通用行为约束，用来减少 AI 编码与文档加工中的常见错误。

优先级必须明确：`latex-maki-math` 的项目规则是父规则；外部 skill、通用 guideline、其他 AI 记忆都是子规则。发生冲突时，必须优先服从本文件中的项目定位、LaTeX 内容规范、真题加工规范、输出验证和任务记录要求。

`karpathy-guidelines` 不替代本项目的 LaTeX 与真题加工规则，而是作为执行前置原则：

1. 先想后写：不确定时先说明假设或提问，不能把模糊需求悄悄解释成自己的版本。
2. 极简优先：只做当前任务需要的最小改动，不额外增加未要求的功能、抽象或配置。
3. 精准手术：只改和目标直接相关的文件与段落，不顺手重构、改格式或删除旁边看似“不顺眼”的内容。
4. 目标驱动：把任务转成可验证目标，例如“生成 PDF 并确认文件存在”“题号连续且无答案残留”“LaTeX 编译通过”。

遇到讲义、试卷、脚本或项目治理任务时，AI 应先写出一句成功标准，再进入修改；小于 1 分钟的显然任务可直接执行，但仍要保持改动最小。

## 跨 AI 记忆导入

如果用户提供其他 AI、IDE Agent、Hermes、Alma、OpenClaw、Obsidian 或聊天记录中的记忆与上下文，先按 `docs/跨AI记忆导入工作流.md` 处理：

1. 原始导出先归档，不直接覆盖项目规则。
2. 先去敏，再摘要、分层、建索引。
3. 区分长期稳定偏好、项目状态、可复用流程和近期临时上下文。
4. 对路径、依赖、API、脚本状态等易变化事实，必须现场验证。
5. 只把稳定且可执行的规则写回 `AGENTS.md`、`docs/` 或任务记录。

## LaTeX 内容规范

- 讲义正文优先使用 `main.tex`、`maki-math.sty` 和 `chapters/` 的现有结构。
- 风格保持简洁、干净、数学优先，避免复杂装饰、花哨标题页和无教学价值的套话。
- 数学符号优先使用 `\geqslant`、`\leqslant`，填空题使用 `\fillin`。
- 题目、定义、定理、例题、练习优先使用样式包已有环境。
- 大段新增内容必须检查公式括号、变量定义、条件限制和结论范围。

## 真题与讲义加工规范

- 拆分试卷时保留原题编号、图片、表格和必要上下文。
- 只要用户要求“仅题目版”，就删除解析、答案、提示和教学备注。
- 生成教师版时，解析要服务于教学，不只堆计算步骤。
- 母题与变式要说明“相同结构、变化条件、迁移方法”，不能只做表面相似。
- 图片必须紧跟相关题目，不能集中堆在文末。

## 输出与验证

常见验证方式：

- LaTeX：用 XeLaTeX 或项目已有脚本编译，检查是否生成 PDF。
- HTML/KaTeX：用浏览器或截图检查公式是否渲染、页面是否溢出。
- Markdown：检查标题层级、题号连续性、图片路径、是否残留答案解析。
- 项目治理：检查新增文档是否能从 README 或根目录规则找到。

如果因为环境、权限或依赖无法验证，必须在任务记录中写清楚原因。

## 自我复盘要求

每次任务结束都要留下三类信息：

- 复盘：本次做了什么、哪些判断有效、哪里有风险。
- 迭代：哪些步骤可以变成固定流程、模板或脚本。
- 进化：下次遇到同类任务时，AI 应自动采用什么规则。

任务记录统一写入 `00-索引与配置/任务执行记录.md`。
