## 一、这次阅读后的核心判断

### 1. 你的数学资料库已经有“原料层”和“加工层”

当前库里至少已经存在四层内容：

- **原料层**：`0-一模-二模-模考试卷-md版本/`、`试卷 latex 化/`
- **教材层**：`03-上海教材md/`、`01-教材原文-只有文本 没有图片/`
- **切片尝试层**：`切片库-ai/`、`沪教版必修第三册2026-切片卡片版/`
- **索引/脚本层**：`00-索引与配置/`、`10-工具脚本/`、若干 `auto_label_*.py`

这意味着你现在的问题，不是“有没有资料”，也不是“能不能转成 md”，而是：

1. 试卷切片还没有形成**统一规范**
2. 现有脚本更偏**索引和标签补录**，还没有一条稳定的**单题切片流水线**
3. 切片产物还没有完全对齐后续用途：AI 讲题、专题组卷、错题诊断、教师备课

### 2. 语文试卷切片库最值得借鉴的不是目录名，而是方法论

从语文库里，最值得继承的是这五点：

- **先定义切分工作流，再批量生产**
- **统一 frontmatter，而不是靠文件名硬编码信息**
- **切片后保留来源、区名、考试类型、年份**
- **把图片处理纳入主流程，不当作例外**
- **把“附加材料”纳入体系，例如阅卷反馈、样卷、评分标准**

数学版不能照抄语文版的板块目录，但必须继承这套工程纪律。

### 3. 数学切片化的最佳原料不是 PDF，而是 `*-dollar.md`

在 `试卷 latex 化/` 和 `0-一模-二模-模考试卷-md版本/` 里，已经出现了一种非常关键的半结构化中间态：

- `xxx-dollar.md`
- `images/`
- `result.json`

这三者的价值非常高：

- `dollar.md` 便于按题号切块
- `images/` 便于给题目绑定图形
- `result.json` 便于追踪页码、图像来源、OCR 质量

所以未来主流程不应该是：

`PDF -> 直接切片`

而应该是：

`PDF -> 标准中间态（md + images + result.json） -> 单题切片 -> 结构化标注 -> 质检`

## 二、未来目标：你最终要得到什么

我建议把“试卷切片化”的最终目标定义成下面四个产物层。

### A. 试卷原子题库层

每道题都是一个最小复用单元，必要时细到小问。

每题至少包含：

- 题目
- 答案
- 解析
- 图片
- 来源元数据

### B. 结构化标签层

每题有统一标签，至少包括：

- 年份
- 区
- 考试类型
- 题号
- 题型
- 分值
- 难度
- 主模块
- 子知识点
- 方法标签
- 是否压轴
- 是否新定义
- 是否有图

### C. 教学复用层

基于切片题库，可以自动拼出：

- 专题讲义
- 分层训练
- 一模二模同题型对比
- 某知识点易错题集
- AI 讲题卡

### D. 质检与回流层

任何切片都可以被检查和修正：

- OCR 是否错
- 图是否丢
- 答案是否串题
- 难度是否失真
- 标签是否跑偏

这个层如果没有，切片库会很快失控。

## 三、建议的总体架构

### 1. 分三层目录，不要把所有产物混在一起

建议未来固定成：

```text
数学试卷切片库/
├── 00-规范与索引/
├── 01-原始中间态/
├── 02-单题切片库/
├── 03-聚合专题库/
└── 90-质检与修订/
```

对应关系如下：

- `01-原始中间态/`
  - 存 `dollar.md`、`result.json`、原图、原始 PDF 路径映射
- `02-单题切片库/`
  - 存真正的题目级切片
- `03-聚合专题库/`
  - 由单题切片二次拼装出的专题讲义、训练集、卡片集
- `90-质检与修订/`
  - 记录修正日志、错误样例、人工复核结果

### 2. 以“单题”为主切粒度，以“小问”为辅切粒度

推荐原则：

- `1-16` 题：默认单题
- `17-21` 题：题目级 + 小问级双层切片
- 对汇编类材料：允许按题目来源再加一层来源字段，不要强行单独建目录

### 3. frontmatter 才是核心数据，不是文件名

文件名只解决“排序”和“粗定位”，不要承担全部语义。

数学版 frontmatter 至少建议包括：

```yaml
title:
subject:
module:
module_name:
function:
exam:
year:
class:
district:
question_no:
subquestion_no:
question_type:
score:
difficulty:
source:
source_pdf:
source_md:
knowledge_points:
methods:
answer_type:
has_figure:
is_key_question:
is_new_type:
tags:
```

你现有的 `试卷元数据标准.json` 已经打了基础，但它更偏“整张试卷描述”，后面要补一个“单题切片元数据标准”。

## 五、建议的切片化主流程

### Phase 0：规范先行

先定四份文件：

1. `数学试卷切片工作流.md`
2. `数学单题元数据标准.json`
3. `数学切片命名规范.md`
4. `数学切片质检清单.md`

这一阶段的目标不是出题，而是让后面不会越做越乱。

### Phase 1：先统一原料入口

目标：所有待切试卷，先变成统一中间态。

建议统一标准：

- 一个试卷目录一个 bundle
- bundle 内必须有：
  - `source.pdf`
  - `paper-dollar.md`
  - `result.json`
  - `images/`
  - `manifest.json`

如果某套卷只有 PDF 没有中间态，先走“转中间态”，不要直接切。

### Phase 2：建立“切片器”

切片器的职责非常明确：

1. 识别题号边界
2. 识别 `【答案】`、`【解析】`
3. 识别 `17-21` 题的小问边界
4. 搬运并重命名图片
5. 输出 `题目 / 答案 / 解析`
6. 生成 frontmatter

注意：

- 切片器只负责结构拆分
- 不负责复杂教学润色
- 不负责最后定稿标签

### Phase 3：建立“标注器”

标注器负责给切片补齐教学语义：

- 主模块
- 子知识点
- 方法
- 难度
- 是否压轴
- 是否新定义
- 是否经典
- 易错点

建议采用：

- 规则初标
- LLM 辅助补标
- 人工抽检校正

### Phase 4：建立“质检器”

质检器至少检查：

- 是否所有题号都切到了
- 是否答案和题号一一对应
- 是否图片引用有效
- 是否 YAML 可解析
- 是否 17-21 题小问完整
- 是否答案层和解析层串题
- 是否明显 OCR 错误未修

### Phase 5：建立“专题聚合器”

当单题库稳定以后，再做二次产品：

- 按知识点聚合
- 按方法聚合
- 按难度聚合
- 按区对比聚合
- 按年份演化聚合

这时候 `切片库-ai/` 就可以从“人工专题产物”升级为“由单题库自动生成的专题层”。

## 七、你未来最该避免的三个坑

### 坑 1：把“切片”和“讲义生成”混成一步

这会导致：

- 一旦讲义模板变了，题库也要重做
- 原始题目和教学改写混杂
- 无法回溯来源

正确做法：

- 切片是“事实层”
- 讲义是“表达层”

### 坑 2：过早追求完美标签

如果一开始就要求每题都：

- 完美知识点
- 完美方法标签
- 完美难度
- 完美易错点

那项目会卡死。

正确做法：

- 第一版只要切出来
- 第二版补主模块和题型
- 第三版补细标签和教学信息

### 坑 3：继续用“文件级索引”代替“题目级结构”

你现在很多索引脚本本质上还是：

- 识别文件名
- 给文件一个大类
- 粗略入库

这对讲义选材帮助有限。

未来一定要转到：

- 一题一记录
- 一题一元数据
- 一题可复用

## 八、我对你需求的理解

我现在理解你的真实目标，不只是“把 PDF 切开”，而是要建立一个可长期积累的数学题库底座。

这个底座至少要支撑四种典型场景：

1. 老师备课时按知识点快速找题
2. 按难度和题型快速组卷
3. AI 对单题进行讲解、变式、错因诊断
4. 把单题进一步长成专题卡片、讲义和 PPT

如果这个理解是对的，那么“试卷切片化”的最优方案就不是做很多小脚本，而是做一条标准生产线。

## 九、我建议的决策顺序

后面真正推进前，建议你先依次拍板以下 5 个问题：

1. **切片主单位是否确定为“单题”，17-21 题同时保留“小问层”？**

4. **第一版是否接受“先结构正确、后精修 OCR/标签”的策略？**
5. **切片的最终主要服务对象，是“老师备课组卷”优先，还是“AI 讲题/卡片生产”优先？**

这五个问题会直接决定目录、元数据和质检标准。
